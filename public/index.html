Control de versiones con Git y GitHub

Un sitio publicado de forma automática: cada cambio se guarda en el historial, se revisa mediante una rama y se despliega con un flujo de trabajo de GitHub Actions.

Ver el flujo de trabajo

¿Qué es el control de versiones?

Es un sistema que registra los cambios realizados en los archivos de un proyecto a lo largo del tiempo. Permite volver a una versión anterior, comparar cambios y trabajar en equipo sin sobrescribir el trabajo de otras personas.

Historial

Cada commit es una fotografía del proyecto con autor, fecha y mensaje.

Ramas

Permiten desarrollar una función nueva sin afectar la versión estable (main).

Colaboración

Los pull requests ayudan a revisar y a integrar los cambios de forma ordenada.

Flujo de trabajo utilizado

  1. Crear una rama desde main para cada cambio (feature/...).
  2. Hacer commits pequeños con mensajes claros.
  3. Abrir un pull request hacia main; se ejecuta la revisión automática.
  4. Fusionar (merge) cuando la revisión es correcta.
  5. Desplegar: GitHub Actions publica el sitio en GitHub Pages.
  6. Etiquetar la versión estable con una etiqueta semántica (v1.0.0).

Automatización con GitHub Actions

El repositorio tiene dos flujos de trabajo: uno de integración continua que revisa el sitio en cada pull request, y otro de despliegue que publica el sitio en GitHub Pages cada vez que se actualiza la rama main.
